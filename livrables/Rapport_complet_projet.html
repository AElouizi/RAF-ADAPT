1. Synthèse exécutive

Le projet construit un système en deux étages pour le marché actions marocain : (1) scorer chaque titre et produire une recommandation BUY / NEUTRAL / SELL ; (2) allouer un portefeuille long-only multi-objectifs, puis le backtester hors échantillon.

Quatre cellules factorielles sont évaluées à protocoles identiques. La plateforme affiche C2 (Ridge + régime) comme modèle principal, car c’est la meilleure configuration en Sharpe et en richesse nette sur 84 mois. C3 (hybride) est quasi à égalité en richesse. Aucun écart vs MASI n’est significatif au seuil de 5 %.

C2 rend. net ann.11,26 %
C2 Sharpe1,035
C2 richesse 100202,3
MASI Sharpe0,661

Coût de transaction 0,3 % × turnover L1. MASI : +7,69 % annualisé, richesse 167,2. Equal Weight C3 : Sharpe 1,162 (contrôle « diversification simple »). Creux 2020–2022, rattrapage 2023–2025.

En août 2026, le pipeline a été refactorisé en architecture multi-agents (Feature, Sélection, Allocation, Backtest, Évaluation, Orchestrateur) sans modifier les modèles, hyperparamètres, NSGA-III ni résultats historiques. L’onglet Administration pilote cette chaîne ; l’investisseur continue de voir le livrable figé.

2. Contexte et objectifs

La Bourse de Casablanca est un marché frontière : liquidité hétérogène, historique plus court, publication semestrielle, frictions de transaction. Un classement de rendement brut est insuffisant.

  • Recommandation mensuelle par titre (BUY / NEUTRAL / SELL) sur l’univers complet.
  • Portefeuille investissable : long-only, poids max 10 %, arbitrage alpha / risque de queue / liquidité.
  • Performance nette de frais vs MASI et vs équipondéré du même univers.
  • Plateforme de consultation + traçabilité scientifique (reproductibilité de thèse).

Le système ne prédit pas un cours brut, n’exécute pas d’ordres, et n’inclut pas le TFT (exploré puis écarté du livrable opérationnel).

3. Gouvernance scientifique

Principes non négociables. Point-in-time (aucune information future). Fondamentaux datés à la publication BVC (S1 fin septembre, S2 fin avril N+1). Walk-forward 36 mois de train / 6 mois de test. Graine random_state = 42. Poids et recommandations historiques figés : la plateforme visualise, elle ne réentraîne pas.
  • Horizon de cible : 63 séances (~3 mois).
  • Rebalancement mensuel, fin de mois de décision.
  • Liquidité : objectif Pareto uniquement — pas de filtre VMQ ≥ 500 000 MAD.

Données BVC → Features → Score α (C1–C4) → BUY/NEUTRAL/SELL → NSGA-III (α, CVaR, L) → Knee (wi ≤ 10 %) → Backtest net → Évaluation → Plateforme

4.2 Indicateurs

Techniques : momentum 1/3/6/12 mois, RSI 14, distances MA20/50/200, vol 20/60 j, vol baissière 20 j, bêta MASI, VMQ 20/60 j. Fondamentales : PE, PB, EV/EBITDA (hors financiers), ROE, marges, croissances, gearing, Piotroski, score santé. Marché : momentum 3 mois MASI, dispersion, breadth MA50.

Cible : α ajusté au risque = (rendement à terme titre − rendement à terme MASI) / volatilité baissière 20 j. Features continues en z-score cross-sectionnel par date.

4.3 Régime

HMM abandonné (état haussier trop rare). Règle à seuils à trois états, terciles calibrés uniquement sur 2015–2020 puis figés : momentum −1,67 % / +4,29 % ; breadth 39,3 % / 59,6 %. Haussier = les deux au-dessus du tercile haut ; baissier = les deux en dessous ; sinon neutre. Indicatrices is_bull / is_neutral / is_bear pour C2 et C4.

5.1 Règle BUY / NEUTRAL / SELL

  • Benchmark interne = 0 (battre le marché ⇔ α > 0).
  • τ = quantile 33 % des |prédictions| des plis passés (expanding, anti look-ahead).
  • BUY si α > +τ ; SELL si α < −τ ; NEUTRAL sinon.
  • À l’étage 2 : SELL exclus ; BUY × 1 ; NEUTRAL × 0,5.

7. Backtest, benchmarks et tests

  • Poids figés à t ; appliqués sur (t , tnext] ; dernier mois 2025-06 détenu jusqu’au 2025-07-31.
  • Coût 0,003 × Σ |Δw| le premier jour de détention.
  • Benchmarks : MASI (même calendrier) ; Equal Weight de l’univers BUY+NEUTRAL de la même cellule.
  • Tests : bootstrap IC 95 %, t apparié, Wilcoxon ; significatif seulement si les deux tests < 5 %.

10. Architecture multi-agents

Objectif : transformer le pipeline de scripts en chaîne d’agents avec mémoire partagée (Supabase, repli JSON local), sans nouvelle expérimentation. 

ADMINISTRATEUR
      │  onglet Administration / Agents
      ▼
 ORCHESTRATEUR  (PENDING / RUNNING / SUCCESS / FAILED)
      │
      ├─ Feature Agent      → FEATURES_READY
      ├─ Selection Agent    → SELECTION_READY     C1–C4 inchangés
      ├─ Allocation Agent   → ALLOCATION_READY    NSGA-III inchangé
      ├─ Backtest Agent     → BACKTEST_READY
      └─ Evaluation Agent   → EVALUATION_READY
              │
              ▼
     tables agent_* (run_id, période, cellule, version, paramètres)
              │
              ▼
     dashboard investisseur (mart figé)

10.1 Principe

Chaque agent a une responsabilité, des entrées, des sorties, un statut et des logs. Ils ne s’appellent pas en dur : l’orchestrateur attend le SUCCESS (événement *_READY) avant de lancer le suivant. Un FAILED arrête tout.

10.2 Mode par défaut ingest_frozen

Publication traçable du livrable 2018-07 → 2025-06. Aucun réentraînement. compute_new est refusé sur cette fenêtre pour protéger la thèse.

10.4 Validation architecture

Tests : py -3 bvc_recommender/agents/test_orchestrator.py — réussis le 15 août 2026. Checksums du livrable FINAL et du mart identiques après ingest ; Feature FAILED bloque la suite ; recalcul figé interdit.

SQL une fois : bvc_recommender/scripts/sql/create_agent_tables.sql. CLI : py -m bvc_recommender.agents --mode ingest_frozen --cells 1,2,3,4.

11. Limites et précautions

  • Pas de recommandations avant juillet 2018 (36 mois de train après panel 2015).
  • Volumes 2023+ encore partiellement incomplets.
  • NSGA stochastique (graine fixe) ; turnover élevé (~1 en L1).
  • L’équipondéré du même univers est souvent compétitif : l’allocation n’est pas un « alpha gratuit ».
  • 2020–2022 difficile ; la surperformance 2023–2025 pèse sur la moyenne.
  • Écarts vs MASI non significatifs à 5 % : lecture économique, pas preuve statistique.
  • L’administrateur reste responsable de l’alimentation des tables marché / fondamentaux.
